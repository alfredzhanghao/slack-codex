# Slack Codex Bridge 使用说明 — 0.3.0a16

适用版本：**0.3.0a16**。更新日期：2026-11-03。验证范围见 [当前验证记录](verification.md)。

## 会话和技能

在 codex 私信发送 `!project`，选择项目，再打开会话并进入该会话的消息列。
同一会话重复打开时复用原根消息；普通任务、回复、审批和附件均留在这一消息列。
未绑定的顶层文本或附件会提示先选择会话，不会送到最后打开的会话。

主卡保留控制权、进入消息列、Settings 和刷新；任务运行时显示 Stop。
Model、Reasoning effort、Skills、Compact、Fork 和文件选择在 Settings 中。
发任务前仍需 Take control，重连后需重新取得控制权。

Take control 只在任务空闲时接管输入。当前会话仍在执行任务时，应使用 Steer 给该任务
追加要求；接管被拒绝不代表已取得控制权。等任务完成、会话卡片刷新后再点 Take control，
确认卡片显示 Slack 控制模式后发送新任务。已明确 rejected 的请求不会自动重发。

Skills 每页显示 8 项，名称后跟简短说明，不在主列表展开完整本地路径。
同名项有序号；Details 显示精确路径，Use skill 始终选择该路径对应的技能。
`!skills 关键词` 可以过滤。没有可靠简短说明时提示查看 Details，不截断长句冒充摘要。

## 文件输入和取回

把图片或文档发到已绑定的会话消息列：

- 文字和附件一起发送：全部文件下载、检查成功后，只提交一次完整任务。
- 只发附件：暂存并回执，不启动任务；10 分钟内在同一消息列发送指令，使用一次暂存上下文。
- 暂存附件配合技能：发送 `!skill 精确路径 -- 任务`。存在暂存附件时，技能表单会提示改在消息列提交，避免漏掉附件。
- 断线或重启：旧附件上下文失效；下一条指令会明确提示重发，旧事件不会自动重放。

每个完整输入最多 5 个文件，单个不超过 10 MiB，总计不超过 20 MiB。
沿用现有支持的文件扩展名和凭据路径限制。普通任务内容不做敏感词过滤。
下载只接受已认证 Slack 文件元数据中的受限 HTTPS 地址，不携带认证跟随重定向。
缺少 `files:read` 或文件不可访问时明确失败，不自动修改 App 权限。

文件存放在独立数据目录的 `attachments/会话ID/批次ID/`，不覆盖项目文件。
图片通过 native localImage 输入传递；文档以实际本地路径作为任务上下文。
24 小时后文件不再可用作新输入，过期的自有批次在下次附件暂存时清理。
这不承诺模型永久保留文件全文。

取回文件可发送“请把上次任务的 Word 文件发给我”或 `send me the Word file from the last task`。
只匹配该会话最近任务明确引用的产物；唯一匹配才实际上传，多项匹配先显示文件选择卡。
指定不存在的文件名不会替换成同类型的其他文件。取回不重跑生成任务。
显式后备命令仍为 `!artifacts` 和 `!artifact "PATH"`。不确定的上传结果不会自动重试。

## Windows 管理器

a16 候选守护程序打开后会扫描已有 Codex 实例。在列表选择目标，点 **Connect selected**，
核对 PID、程序路径、版本和后端端口后确认。点 **Refresh instances** 会清除旧选择。
启动/恢复时发现已有桌面也会进入选择流程，不自动重启它。

只有实际开放了兼容共享连接的实例才能直接接入；私有 stdio 等不兼容实例会显示原因，
保持原样运行。确认选择不会凭空创建接口。选择超过两分钟或进程身份变化时需要刷新。
桥接仍连接其他实例时，先明确 Stop，再选择新的实例。

本机快捷方式仍使用固定 a15 安装；本次源码开发不会自动替换它。a16 部署需在 AGY 审查、
CI 和合并后另行处理。退出后使用同一快捷方式重新打开。
安装和恢复细节见 [运行维护说明](operations.md)。

安装包提供无控制台入口 `bridge-supervisor.exe`，需指定已核对的私有部署清单、
operator 脚本和 profile。示意命令（占位符需要替换成本机实际物理路径）：

```text
bridge-supervisor.exe --deployment C:\physical\deployment.json --operator C:\physical\bridge_operator.py --profile p5
```

部署清单仍须固定包版本、模块/配置/operator 哈希、实际 pythonw 路径和状态目录。
旧 a14 worker 缺少新的 native_chain 身份证明，不能被管理器当作已验证的新 worker 接管；
升级需准备独立安装和清单，保留原安装、数据库和回退资料。
管理器不读取凭据文件；启动时从既有环境变量获得凭据。

- Start / Restore connection：有桌面时先选择确认；没有桌面时才走原有明确的受控启动。
- Stop：仅停止本管理器明确接管或启动的桥接，不停止桌面、后端或 native 任务。
- 关闭窗口：隐藏窗口；点击托盘图标可打开状态窗口。
- Exit：停止受管桥接并退出监控；停止未确认时保留窗口和错误，不强杀进程。

桌面关闭会暂停桥接；监控不会反复重开桌面。其他桌面已打开时要求人工核实，
不强制绑定或另开后端。意外 worker 退出只在身份可验证时最多恢复 3 次，退避为 2/4/8 秒。
人工 Stop、身份/权限/存储错误、状态不确定都不会自动重新启动。
无开机启动项、登录注册或循环计划任务。

## 无人值守本地检查

当前固定版本的 Windows Codex 可选择 **Existing desktop IPC**，确认后复用现有桌面，
无需关闭或重启。先在 Codex 打开需要控制的聊天，再通过 Slack 接管。此模式支持普通任务、
附件、精确 Stop、最终回复和文件取回；Steer、审批、模型/Skills 设置、Compact、Fork
请在 Codex 桌面处理。不可用的按钮会隐藏。共享 WebSocket 模式保留原有完整功能。
新版本源码需要经过审查并更新固定运行安装；修改源码本身不会替换正在运行的管理器。

执行 `scripts/check_open_issues.ps1`，自动完成全量 pytest、ruff、编译、构建、
归档完整性检查、离线安装和安装后导入检查。每次产生独立的
`.work-issues/verification-UUID/result.json` 和日志，不读取凭据、不部署、不发送 Slack 消息。

## 常用检查和异常处理

- `!status`：查看连接和账户限额；在对应会话线程中可查该会话。
- `!op OP_ID`：核对具体任务或文件传输记录，accepted 不等于任务已完成。
- `!roots`：检查已绑定入口；入口丢失时先检查，再明确确认重建。
- 任务执行中使用 Steer 追加要求，Stop 中断当前任务；不要反复 Take control。
- 设置模型和推理强度只作用于下一次提交，不改变正在执行的任务；提交前核对卡片。
- 普通回复不再附操作编号、成功回执或账户额度，详细信息通过显式命令查看。
- unknown 表示结果不确定，先查原生桌面与操作记录，不重发任务、上传或审批。
- 锁屏不等于断线；休眠、重启或断网恢复后先检查连接，再刷新和接管。
